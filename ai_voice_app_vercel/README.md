## 今回の改修内容 (v3.6.0 ログイン＋途切れ対策、2026-11-20)

1. **ログイン画面**: API利用のためログイン必須にしました。ID/パスワードの平文はコードに書かず、Vercel環境変数 `LOGIN_ID_HASH` / `LOGIN_PASSWORD_HASH`（SHA-256ハッシュ）と比較します。成功時はHMAC署名付きセッションCookie（7日間）を発行し、`/api/token` と `/api/rest` はCookieなしでは401を返します。

## 今回の改修内容 (v3.4.2 トークン発行修正、2026-11-20)

詳細エラー: `INVALID_ARGUMENT: Invalid JSON payload received. Unknown name "liveConnectConstraints" at 'auth_token': Cannot find field.`

1. **プレーントークン化**: 生 REST（`POST /v1beta/auth_tokens`）では `liveConnectConstraints` フィールド自体が受け付けられませんでした。公式の簡略例どおり `uses` / `expireTime` / `newSessionExpireTime` のみで発行するようにしました（`api/token.js` / `api/server.py`）。モデル・設定はクライアントの setup メッセージで指定します。トークンは単回（uses 1）・短命（開始2分／接続30分）のままです。モデル固定はしません（利用制限・アカウントは次フェーズで必須）。
2. **接続先の修正**: クライアントの WebSocket 接続先が通常版 `BidiGenerateContent` になっていたため、エフェメラルトークン用の `BidiGenerateContentConstrained`（v1beta、`access_token`）に直しました。
3. **詳細エラーは維持**: 失敗時は引き続き Google の詳細エラー（`error.message` / `error.status` のみ）を 502 に含めます。

## パートナー写真の差し替え手順（6バリエーション）

現行の写真は、旧デザイン時の静止画JPG 3枚を一時的に使っています（`public/assets/cyber_holo_face.jpg` など。ファイル名は旧名称のままです）。写実系・日常系の新写真が用意できたら、次の手順で差し替えてください。

1. 写真を用意する（写実的・日常の服装・自然な背景。SF・サイバー要素なし）。推奨：正方形、1024×1024以上。
2. WebPに変換して軽量化する（例：`cwebp -q 80 入力.jpg -o 出力.webp`）。ファイルサイズは1枚200KB以下を目安にする。
3. `public/assets/` に置く。ファイル名の例：`haru.jpg` → `haru.webp`、`luna.webp`、`ren.webp`、`misaki.webp`、`kenji.webp`、`satoko.webp`。
4. `public/index.html` の `characters`（`holo` / `luna` / `ren`）の `image` を新しいパスに変える。ミサキ・ケンジ・サトコは現在HTMLの「写真準備中」カードなので、写真が用意できたらそのカードを有効な選択ボタンに変え、対応する `characters` エントリーと声を追加する。

## 今回の改修内容 (v3.1 会話流暢化、2026-11-19)

会話が成り立たない原因だった setup／ターン判定／VAD／割り込み／再接続を直しました。実機ライブ音声は未検証です。

1. **setupを仕様通りに**: `responseModalities` を `['AUDIO']` のみにし、`inputAudioTranscription` / `outputAudioTranscription`（言語 `ja-JP`）を setup に入れました。VAD感度を `START_SENSITIVITY_HIGH` / `END_SENSITIVITY_HIGH` に直しました。setupの再送はやめ、感情・強さの変更は `clientContent` でのシステム指示更新、パートナー（声）の変更は再接続で行います。
2. **ターン判定をゆるめた**: クライアント無音 220ms → 600ms、サーバー `silenceDurationMs` 200ms → 500ms。言いよどみ・間で切れにくくしました。
3. **VADのしきい値暴走を防止**: `noiseFloor` のEMA更新は無音フレームのときだけにしました。既定の割り込み感度をコードと画面で `normal` に統一しました。

5. **切断・再接続**: `data.error` / `goAway` / `sessionResumptionUpdate` を画面に表示し、setupに `sessionResumption` を入れました。1006等は指数バックオフで最大3回自動再接続、1007（setup不正）は設定エラーとして再接続しません。開始ボタンの連打による二重接続を防ぎ、キー取得のfetchに5秒タイムアウトを入れました。

- **キー露出は v3.4 で停止（マージ・デプロイ済み、キー交換済み）**: `/api/key` の生キー返却は廃止し、一時トークン化しました。新キーは発行済みで Vercel 環境変数に登録済み、旧キーは削除済みです。ただしトークン化は「キーの盗難」を止めるだけで、アカウント・無料枠・レート制限がない現状では `/api/token` 自体が公開の発行口になり、利用量の「タダ乗り」は止まりません。アカウント・無料枠・利用制限・Stripe決済・利用規約は次フェーズで必須です。v3.4.1 でトークン発行の 400 エラーを修正しましたが、実キーでの接続確認は未検証です。
- **パートナー写真は旧画像のまま**: 上記の差し替え手順の通り、写実系の新写真への差し替えはまだです。
- **決済は未実装**: v3.2でプラン表示（Free / Plus）のUIだけを置きました。購入ボタンは「準備中」で無効化してあり、実際に課金はできません。アカウント・無料枠・利用制限・Stripe決済・利用規約は次フェーズです。
- **フォールバック経路は非ストリーミングのまま**: Live API切断時は数秒遅くなることがあります。
- **PWAは基盤のみ**: v3.3で manifest と共有メタを入れましたが、Service Worker（オフラインキャッシュ）と正式な 192/512px アイコンPNGは未導入です。Service Worker はプレビュー環境で更新挙動を確認してから入れます。シート背景の `inert` 化も次段階です。

## Vercel へのデプロイ手順

1. **GitHub リポジトリへプッシュ**:
   `ai_voice_app_vercel` 以下のコードを GitHub にプッシュします。

2. **Vercel ダッシュボードでインポート**:
   - [Vercel Dashboard](https://vercel.com/) にログインし、「Add New Project」からリポジトリを選択します。
   - Root Directory を `ai_voice_app_vercel` に指定します。

3. **環境変数 (Environment Variables) の登録**:
   Vercel のプロジェクト設定画面で以下の環境変数のいずれかを登録します：
   - **Key**: `GEMINI_LIVE_API_KEY`（または `GEMINI_API_KEY`）
   - **Value**: Google AI Studio で取得した Gemini API キー

4. **デプロイ完了**:
   デプロイ後、公開URLにアクセスすると接続時に Vercel サーバーレス関数（/api/token）から一時トークンが発行され、音声対話が可能です。生キーはブラウザに渡りません。

## ローカル実行手順

```bash
# ai_voice_app_vercel ディレクトリで実行
python api/server.py 8080
```
ブラウザで `http://localhost:8080/` を開き、マイクを許可して「会話をはじめる」を押してください。
