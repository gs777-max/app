# ゴルフ試打クラブ＆計測結果 管理表ツール — 問題課題の洗い出し

元ファイル：ユーザーが 2026-11-23 にアップロードした
`20261123______________________2026___2026.html`（93,811バイト、単一HTML）。
分析日：2026-11-24。データは `DEFAULT_SESSIONS` 49件をプログラムで再計算して検証した。

## 要約

ツール自体はよくできている（4タブ、自動ランキング、A/B比較、因子別集計、CSV/JSON入出力）。
ただし**「誰が打ったか」がどこにも無い**うえ、**編集するとデータが消えるバグ**と、
**画面の集計数字が実データと食い違っている**問題がある。v1.0 では P0 を修正した。
スコア計算式そのものは v1.0 では変えていない（変えると全セッションの点数・判定が変わるため）。

## P0（致命的・v1.0で修正済み）

### P0-1. 個人名（打者）がどこにも無い ★ユーザーの指摘どおり
- `tester` / `打者` / `プレイヤー` / `氏名` / `名前` の文字列はファイル全体で **0件**。
- データ49件のキー一覧にも打者欄なし。登録フォーム、ランキング表、ログ表、A/B比較、
  フィルタ、CSVヘッダー、JSON のどこにも無い。
- 影響：複数人で試打した場合、誰のデータか判別できない。日をまたいで別人と
  比較しても気づけない。ランキング1位が誰の記録かも分からない。
- v1.0：`tester`（打者・個人名）欄を追加。フォーム／ランキング／ログ／
  ダッシュボードの打者フィルタ（全打者／未記入のみ／個人別）／A/B選択肢／CSV に反映。
  **既存49件の打者は推測で入れていない（すべて「未記入」）**。使う人が登録時に
  入れる運用。1人で使う場合も、後から他人と比較するときに備えて入れておくのが安全。

### P0-2. 編集すると「打ち出し角」と「ミート率」が消える（データ消失バグ）
- 登録フォームに `f-la`（打ち出し角）・`f-sf`（ミート率）の入力欄が無いのに、
  保存処理が `sf: null, la: null` を **固定で上書き** する。
- 47件が持っている `la`（例：S01 は 15.4°）と `sf`（例：S01 は 1.48）を、
  **編集画面を開いて保存しただけで消してしまう**。元に戻せない（localStorage保存後）。
- 同じく `club: '1W'` も固定上書き（現状49件すべて1Wなので実害は無いが、将来の
  FW/UT等の記録を潰す）。
- v1.0：フォームに「クラブ」「打ち出し角」「ミート率」を追加し、保存時に
  入力値をそのまま保存する。編集時の既存値もフォームに読み込む。

### P0-3. 画面の集計数字が実データと食い違う
| 表示 | 実データ（再計算） |
|---|---|
| ヘッダー「全47セッション・463球」「11/12〜11/23」 | 49件。463球は**対象外を含む合計**で、有効は46件・453球。日付は 2026-09-12（H03/H04）を含む |
| ストレージキー `..._49sessions` | 49件は正しい（ヘッダーの47が誤り） |
| リセット確認「全49件・有効46件453球」 | こちらは正しい。同じアプリ内で数字が2種類ある |
- v1.0：ヘッダー副題を実データから自動計算するようにした
  （期間・全件数・全球数・有効件数・有効球数）。今後データを追加・削除しても食い違わない。

### P0-4. JSON読込に検証が無い（全データ消失リスク）
- 旧：配列かどうかだけ確認し、そのまま `state.sessions` を置き換えて保存。
  必須項目なし・ID重複あり・数値が文字列でもそのまま取り込む。
  壊れたJSONを読み込むとランキングも集計も壊れ、元に戻すには「初期データに戻す」
  （＝編集分も全て消える）しかない。
- v1.0：`id`/`head`/`shaft`/`date` の必須確認、ID重複の拒否、失敗時は
  「現在のデータは変更していません」と明示して置き換えない。

### P0-5. CSV出力が項目落ち＋壊れやすい
- 旧：ヘッダーに打者・クラブ・打ち出し角・ミート率が無い（`la`/`sf`は
  データにあってCSVに出ない）。メモのカンマを空白に置換してごまかしており、
  ダブルクォートや改行を含むメモはCSVとして壊れる。
- v1.0：上記4項目を追加し、RFCに沿った引用符エスケープに変更。
  ヘッダーも「BS・初速」「CS・ヘッドスピード」に明確化。

## P1（判断を歪める・v1.0で注記を追加、式の変更は見送り）

### P1-1. 総合点は「相対順位」で、絶対評価ではない（未説明だった）
- スコアは各指標の最小〜最大を0〜100点に換算する min-max 正規化。
  飛距離スコア＝そのセッション内での相対位置。**セッションを追加・削除・
  有効/対象外の切替をすると、過去の全セッションの点数と判定が変わる**。
- 判定の境目 72点／50点もアプリ独自の値で、根拠の説明が画面に無い。
- v1.0：ランキング下に注記を追加。式の変更はしていない（変えると全点数が変わるため、
  変更するなら別バージョンで合意のうえで）。

### P1-2. スコア計算と「エース超え合格判定基準」がつながっていない
- マスタ画面の合格基準（Carry 268yd / Total 293yd↑、BS 2,600rpm以下、
  Off Pin 19.0yd以内、Side Spin 330rpm以下、ミート率1.50以上）は
  スコア計算に**一切使われていない**。スコアは飛距離・Off Pin・左右幅・
  サイドスピン・±30yd率のみ。
- バックスピン（BS 2,800rpm前後が大半で基準オーバー気味）も、左右バイアスも
  スコアに反映されない。管理ルール3「左右バイアス必須記録」と矛盾する。
- v1.0：注記で明示のみ。今後：絶対基準ゲート（例：基準を満たさないと
  「マッチ」にしない）を入れるか、スコア式に組み込むかの判断が必要。

### P1-3. ±30yd率の欠測が多すぎる（31/46件が未記録）
- 有効46件のうち31件で `fw30` が null。計算上は一律50%で補完されるため、
  未記録のセッションは方向安定スコアの10%分が「真ん中」で固定される。
  記録あり（80〜100%）のセッションと不公平な比較になる。
- 同様に左右バイアスも34/49件が未記録（M系列は全件なし）。
- v1.0：注記で明示のみ。今後：未記録は補完せず「参考」扱いにするか、
  入力時に必須化するかの判断が必要。

### P1-4. 球数が少ないのに平均値だけで順位付けしている
- 1セッション 7〜10球（10球が42件、9球が4件、7球が1件）。
  平均値のブレ（標準誤差）の表示が無く、1球の差で順位が入れ替わる。
  7球の M19（286.8yd）が3位に入っているが、10球換算との比較の注意書きが無い。
- 計測日ごとの体調差を補正する仕組み（管理ルール4「毎回エース基準を10球」）も、
  機能としては実装されていない（ルール文だけある）。

## P2（データの整合性・要確認）

### P2-1. H03/H04（2026-09-12・川口大試打会）は「1行に3シャフト」
- シャフト欄に `24V青6X / 24V赤7X / WB6X` のように3本分を1文字列で記録し、
  数値は全項目 null。管理ルール1「1セッション＝1行・条件分離」に違反し、
  シャフト別集計ではこの行が1つの変なシャフト名として扱われる。
- 定性評価（★★★）のみの行なので「対象外」扱いは正しいが、シャフト別に
  分解して登録し直すか、定性メモ専用の扱いを決めるのがよい。

### P2-2. S08 は S06 の「重複2回目」として対象外（正しい運用）
- メモに理由が明記されており、対象外フラグの運用は正しい。問題なし。
  ただし重複の判定は人手頼みで、同じ条件の2回目を自動で警告する機能は無い。

### P2-3. ヘッドの偏りが大きい
- ELYTE TD 31件、G440 MAX 7件、G440 LST 6件、Quantum TD 4件、Qi4D 1件。
  ヘッド別集計で Qi4D は n=1 のため平均値の信頼性が低い。集計表に件数は
  出ているが、n=1〜2 の行への注意書きが無い。

### P2-4. TOP30シャフト表・ギアマスタに出典・更新日が無い
- 「低トルクシャフト ベスト30（2026年市場版）」の順位・トルク値の出典が不明。
  ギアマスタの公式リンクは PING／Callaway／TaylorMade／三菱ケミカル等で
  確認できるが、スペック値（例：TENSEI Pro Blue 1K 70X＝72.5g／トルク3.3）が
  いつのカタログ値か分からない。カタログ改訂時の陳腐化に注意。

## P3（運用・技術面）

### P3-1. 保存は localStorage のみ（端末・ブラウザ依存）
- サーバー送信なし＝プライバシー面では安全だが、端末を変えるとデータが無い。
  ブラウザのデータ削除・容量オーバーで消える。保存失敗も旧版は無言で握りつぶしていた。
- v1.0：保存失敗時にトーストで警告。JSON保存によるバックアップ運用を推奨。
  （別端末での共有・クラウド同期は今後の課題。個人名を入れる以上、共有時の
  取り扱いも決めておくこと）

### P3-2. CDN依存（Tailwind / Chart.js / Lucide）
- オフラインではデザインとグラフが表示されない。CDNが止まるとアプリ全体が
  動かないわけではないが、見た目とチャートが崩れる。SRIハッシュやフォールバック無し。
- 計測現場（インドアでも電波が弱いことがある）で使うなら、ローカル同梱の検討を。

### P3-3. BS/CS のラベルが分かりにくい
- 旧：フォームは「平均BS(m/s)」「平均CS(m/s)」、ログ表は「BS / CS」、
  ランキング表は「SS(rpm)」。BS＝ボール初速、CS＝ヘッドスピード、
  SS＝サイドスピンと分かる人しか読めない。
- v1.0：「平均BS・初速」「平均CS・ヘッドスピード」「サイドスピン (rpm)」に明確化。
  単位は m/s のまま（yd換算はしていない）。

### P3-4. その他（軽微）
- 「初期データに戻す」は編集分を全て消すのに、事前にバックアップを促さない。
- 削除は確認ダイアログあり（良い）。取り消し（Undo）は無い。
- 日付フィルタの選択肢が「全計測日 (11/12〜11/23)」の固定文言だった
  （v1.0の副題自動計算とは別に、フィルタ文言は従来のまま）。
- スマホ幅での横長テーブルは横スクロール頼み（現状維持）。
